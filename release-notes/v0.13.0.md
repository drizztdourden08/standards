# Standards v0.13.0

Lint and tests now cover only what changed, every step has a hard time limit, and only one heavy check runs at a time on the machine. Tests carry exactly one tag: critical, standard or e2e.

## Upgrading

- Replace the `lint` and `test` scripts with the block in `templates/package-scripts.json`: `test`, `test:pr`, `test:e2e`, `lint` and `lint:all`.
- Build the vitest config from the preset: `defineStandardsVitest()` from `@drizztdourden08/standards/vitest`.
- Give every test one tag, on itself or on its top `describe`: `{ tags: ['critical'] }`. The new rule `local/test-has-one-tag` fails a test with no tag, two tags or an unknown tag.
- CI asks for the lint mode. `CI=1` no longer forces a full lint: pass `--all` on main and releases.
- The reusable CI workflow now runs `test:pr` and checks out the full history, so the base can be found.

## Changes

- `standards lint` lints the files changed against the base branch by default. `--all` lints everything, `--base <ref>` picks the base. Typecheck stays project wide.
- Every lint step has a hard timeout. On timeout it stops the whole process tree it started, by its own pid, and fails.
- `standards test [changed|pr|e2e]` runs only the tests related to files changed against the base: critical, then critical and standard, then e2e. There is no mode that runs every test. A release passes `--base <last release tag>`.
- The preset runs vitest in forks with at most 3 workers, defines the three tags with their timeouts (5 s, 30 s, 120 s), and stops after the first failures.
- One lock for the whole machine, `~/.coord/locks/heavy-check.lock`, makes heavy checks wait their turn across projects. A lock whose process is gone is taken over. `standards run-locked -- <cmd>` runs any command under it.
- The README documents the modes, the lock, the timeouts, the tag rule and how Cargo projects map e2e to `#[ignore]` or a feature.
