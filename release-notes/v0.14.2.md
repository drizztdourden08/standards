# Standards v0.14.2

`standards knip` no longer crashes when an extension adds a knip preprocessor, and the heavy check lock no longer waits forever.

## Upgrading

- Nothing to change. A repo whose `standards knip` failed with `id.startsWith is not a function` now runs.
- A lint or test run that waits for the heavy check lock now gives up after 300 s. Set `STANDARDS_LOCK_WAIT_S` for a longer wait.

## Changes

- knip 5.88 crashes on a second `--preprocessor`. The git-ignored hints plus any extension preprocessor made two. `standards knip` now passes one: with more than one, it writes a chain module under `node_modules/.cache/standards` that runs them in order.
- The wait line of the heavy check lock names the holder and how long it has held the lock, and repeats each minute. Past the wait limit the run fails with an error that names the holder.
