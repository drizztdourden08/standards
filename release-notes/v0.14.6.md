# Standards v0.14.6

The heavy check lock has slots, so three heavy checks run at once and a long queue gives up later.

## Upgrading

- Nothing to change.
- The lock files are now `heavy-check.0.lock`, `heavy-check.1.lock` and `heavy-check.2.lock` in the lock folder. `lockPath(env, slot)` returns one of them; `legacyLockPath(env)` returns the old file.
- `STANDARDS_LOCK_SLOTS` sets the slot count. It takes an integer of 1 or more; any other value means 3. `STANDARDS_LOCK_WAIT_S` still sets the wait.

## Changes

- A heavy check takes the first free slot and writes its slot into the holder text, such as `slot 1 of 3`. A dead holder pid frees its own slot.
- A live `heavy-check.lock` from an older standards version counts as one more holder, so old and new versions do not overrun the machine. A dead one is ignored.
- The default wait is 1800 s, up from 300 s. The gave up error and the wait line name every holder with its slot, pid and job.
- `standards test e2e` and app launches take no slot, so they never queue behind a lint. Lint, the `changed` and `pr` test modes, and `standards run-locked` use the slots.
