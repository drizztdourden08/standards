# Standards v0.14.7

The heavy check lock no longer waits on a holder that died, even when another process took over its pid.

## Upgrading

- Nothing to change.
- A lock written by 0.14.7 records `heartbeat: true`. Older slot files and a legacy `heavy-check.lock` keep the old rule, so mixed versions still share the lock.

## Changes

- A running holder touches its lock file every 10 s from a worker thread, so a job that blocks in `spawnSync` keeps its lock fresh.
- A holder is alive only while its pid exists and, when its lock has `heartbeat: true`, the file was touched in the last 60 s.
- A pid reused by a later process no longer keeps a dead holder alive. The check reads no process start time and runs no script host.
